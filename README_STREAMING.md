# 这是一个工艺参数持久化的项目

1. MySQL 执行 `schema.sql`
2. 将 `HT_*.xlsx` （teacher给的实际数据表格）放入本目录
3. `python main.py`

## 自动化测试（依旧shit）

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

`tests/test_completeness_accuracy.py` 用构造数据证明：8 项齐全时字段无空、数值与原始格一致；并覆盖速度排他、主机/辅助螺杆、带单位、`/` 缺失等情形。

结构：`core`（领域对象与清洗逻辑）、`io_utils`（Excel 与数据库）、`main.py`（流水线编排）。

## 🔧 使用方法

### 普通模式（推荐）
```bash
python main.py
```

**特点**：
- 逐文件处理，避免内存堆积
- 默认批处理大小：1000条/批
- 内存阈值：5000条时触发垃圾回收
- 适合大多数场景

### 大文件模式（超大Excel）
```bash
python -c "from main import main_for_large_files; main_for_large_files()"
```

**特点**：
- 分块读取Excel（1万行/块）
- 更大的批处理大小（2000条/批）
- 适合50万行以上的超大文件

## 🎯 性能优化点

### 1. 内存管理
- **逐文件处理**：处理完一个文件就释放内存
- **批量入库**：每1000条记录入库一次
- **强制GC**：定期触发垃圾回收

### 2. 数据库优化
- **连接复用**：减少连接创建开销
- **批量提交**：提高写入效率
- **错误处理**：支持事务回滚

### 3. 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `BATCH_SIZE` | 1000 | 每批入库的记录数 |
| `MEMORY_THRESHOLD` | 5000 | 内存阈值，触发垃圾回收 |
| `chunk_size` | 10000 | 大文件分块大小 |

## 📊 处理流程

```
[Excel文件1] → [读取] → [验证] → [批量入库] → [释放内存]
[Excel文件2] → [读取] → [验证] → [批量入库] → [释放内存]
    ↓
[处理完成] → [显示统计]
```
